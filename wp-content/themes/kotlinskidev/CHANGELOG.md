# Changelog

All notable changes to the kotlinskidev theme are documented in this file. Entries are kept short (2-3 sentences) — for full technical detail on any entry, see the referenced files' own git history/commit messages.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this theme follows [Semantic Versioning](https://semver.org/):

- **MAJOR** — breaking change: removed/renamed a block or attribute, a template/pattern change that requires editors to re-save affected content, a markup change that isn't backward compatible.
- **MINOR** — new, backward-compatible capability: a new block, a new attribute, a new pattern, a new editor control.
- **PATCH** — bug fix, style tweak, security fix with no new capability.

**When releasing:** bump `Version` in `style.css` and `"version"` in `package.json` together (they must always match), move the `[Unreleased]` entries under a new dated version heading, and start a fresh empty `[Unreleased]` section. See `docs/treeview.md` for the full current structure reference — update it alongside any change that adds/removes/renames a block, pattern, template, function module, or test file. See `.claude/skills/sync-docs/SKILL.md` for the full checklist to run before considering any change "done."

**Keep every entry to 2-3 sentences, no exceptions.** Count the sentences before saving. State what changed and why it matters — root-cause narrative, verification steps, and code-level mechanics belong in the commit message or PR description, not here. This file has needed a full re-compaction more than once already because entries crept back up to 5-10+ sentences each; a deep/interesting bug is not an exception to the limit.

### Fixed

- **2026-09-11 — Opening any `kt-modal` (not just `kotlinskidev/marquee`'s) after scrolling far enough down a page no longer snaps `scrollY` backward, sometimes by thousands of pixels.** Root cause: `scroll-lock.ts`'s modal-open state set `overflow: hidden` on `<body>` in addition to `<html>` — `<html>` alone (the real root scrolling element) already blocked scrolling correctly, but `<body>`'s was redundant *and* clipped its own rendered box, shrinking what `<html>` considered scrollable and forcing `scrollY` down to fit. Found via a real Playwright wheel-scroll-then-click E2E repro (`tests/e2e/marquee-modal-scroll-jump.spec.ts`) after synthetic/`scrollTo()`-based reproductions repeatedly failed to catch it — confirmed live via direct `overflow` isolation, same "must be real scroll" pattern already documented in `scroll-section-multi-pin.spec.ts`.
- **2026-09-11 — `modal-manager.ts` no longer lets the browser's own native focus-and-scroll-into-view default action move the page when a modal trigger sits inside a GSAP-pinned section.** `mousedown` on a trigger now calls `preventDefault()` (the standard technique for a control managing its own focus target) since `openModal()` already moves focus to the modal's own close button; `scrollY` is captured at `mousedown`, before any native or app-driven mutation, and a short multi-frame guard re-asserts it if anything still disturbs it afterward.
- **2026-09-11 — `kotlinskidev/marquee` items' focus-visible outline is no longer clipped top/bottom.** `.kt-marquee`'s `overflow: hidden` (needed for the scrolling clip) left zero vertical room for the outline's offset — the left/right edges survived only because they landed in the gap between items. Added vertical padding to the row so the full outline renders on every side.
- **2026-09-10 — `.kt-marquee` now declares `contain: layout paint`, guaranteeing its infinite scroll animation can never force layout/paint on sibling elements outside the block.** `will-change: transform` on `.kt-marquee__track` (previous fix) only hints the browser toward GPU compositing; `contain` is the hard boundary contract that makes leakage to other components structurally impossible, not just unlikely. Verified live — layout, edge-fade mask, and all 10 items still render correctly.
- **2026-09-10 — `kotlinskidev/marquee`'s scrolling track (`.kt-marquee__track`) now gets its own compositor layer (`will-change: transform`, removed under `prefers-reduced-motion`).** Found via frame-by-frame diffing of a screen recording of Chrome DevTools' Styles pane: the panel was repainting on nearly every frame while inspecting the track, pointing at the parent's `mask-image` fade forcing a full repaint of the animated child every tick instead of cheap GPU compositing — unlike the homepage's mostly-paused GSAP animations, this one runs infinitely. Promoting the track to its own layer isolates it from the mask's repaint cycle.
- **2026-09-10 — `kotlinskidev_tracked_build_files()` (`functions/cache.php`) now globs every `build/css/*.css`/`build/js/*.js` file instead of a hardcoded 4-file list, so adding a new block's compiled output busts the deploy fingerprint too.** Found live: `kotlinskidev/marquee`'s new `marquee-init.js` was silently missing from the page (Asset CleanUp's cached bundle predated the block and never picked it up) because the old fingerprint only watched `critical`/`main` — confirmed via a `wp eval` cache purge that immediately fixed it. This closes the whole class of bug for every future new block, not just this one.

- **2026-09-10 — Five more Storybook stories (`nav-banner`, `nav-image`, `nav-paragraph`, `nav-link`, `popular-pages`) rendered a blank canvas for the same reason as the `InnerBlocks` fix above: a dead type-only `import { type X } from "../nav-content"` (or `"./index"`) that never triggered the block's `registerBlockType` side effect.** Switched each to a real side-effect import. `content-tabs`'s built-in tab template (`src/blocks/content-tabs/edit.tsx`, `TABS_TEMPLATE`) now seeds real example copy per tab instead of only a placeholder hint, so both Storybook and a freshly-inserted real block show working example content.
